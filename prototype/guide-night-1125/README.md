# 안내 판단 시제품 (11/25 실제 폰 검증)

Guide 서비스 `/v1/guide/next`의 판단 순서를 실제 폰으로 검증하려고 만든 파이썬 시제품입니다. **서비스 코드가 아닙니다.** Spring으로 옮길 때 로직과 시험 사례를 참고하는 용도입니다.

- WBS: 5.1.3 핵심 문제를 ERD · API에 반영 (근거 자료)
- 담당: 김우석

## 무엇을 확인했나
- 판단 순서: 규칙 → 앱 지식 표 → AI(스크린숏 + Haiku) → AI 답 검사 층
- 실제 폰(갤럭시 S21+)으로 앱 9개: 코레일+ · 배민 · 쿠팡이츠 · 쿠팡 · 네이버지도 · 카카오맵 · 버스타고 · 유튜브 · 요기요
- 「서울역에서 대전 가는 기차표 모레 두 장」 한 문장 → 코레일+ 조회 화면(서울 → 대전, 2명, 모레)까지 안내. AI 호출은 말 해석 1번, 나머지 7단계는 앱 지식 표로 처리
- 결제 · 주문 · 담기 · 예매 · 전송은 0번. 모든 누르기는 `phone.py`의 안전 검사를 거침

## 서비스로 옮길 때 볼 것
| 파일 | 내용 | 옮길 곳 |
|---|---|---|
| `guide_sim.py` | 화면 종류 규칙(`screen_type`), 앱 지식 표(`KNOW`) | Guide 서비스 판단 순서, ERD 「앱 지식」 표 |
| `validate2.py` | AI 답 검사 층: 금지 버튼, AI가 말한 글자 ≠ 그 자리 칸 글자면 다시 판단 | Guide 서비스 검사 층, ERD 「금지 버튼」 표 |
| `mask.py` | 스크린숏 개인정보 가리기 패턴 | 서버 2차 검사. 1차 가리기는 앱(폰 안) |
| `normalize.py` | 말 해석 결과 → 앱 표기(「서울역」 → 「서울」, 날짜) | `/v1/guide/intent` 뒤처리 |
| `phone.py` | 안전 누르기(금지 단어 · 금액 · 화면 바뀜 · 허용 앱 검사) | 시험 도구. 서비스엔 안 옮김 |
| `regress.py`, `validate_regress.py` | 회귀 시험 사례(화면 → 기대 행동 34개, AI 답 → 막을지 13개) | Spring 테스트로 옮김 |

## 알려진 한계
- 앱 지식 표는 11/25에 본 화면을 보고 손으로 쓴 것입니다. 앱 업데이트 · 큰글씨 모드 · 시간대에 따라 깨집니다
- 가리기는 접근성 글자 기반이라 팝업 · 시트 뒤로 비친 글자는 못 가립니다. 실제로 주소 일부가 2번 AI로 갔습니다. 서비스에서는 앱이 폰 안에서 먼저 가려야 합니다
- 잘못 누름은 화면만으로 알 수 없습니다. 앱이 접근성 클릭 이벤트로 실제 누른 칸 글자를 보내야 합니다
- 코레일+ 열차 목록은 접근성 글자가 0개라 스크린숏 판단이 필요합니다

## 실행
### 폰 · API 키 없이 (누구 PC에서나)
필요한 것: 파이썬 3.11+, `pip install pillow`

| 명령 | 무엇 | 기대 결과 |
|---|---|---|
| `python -I regress.py` | 저장 화면 → 규칙 · 앱 지식 표가 고르는 행동 | 34/34 통과 |
| `python -I validate_regress.py` | 저장된 AI 답 → 검사 층이 막을지 · 통과시킬지 + 가짜 화면(금지 버튼 · 표시 칸 · 닫기 강조 보류) + 캡처 전에 멈출 화면 6개. 실패하면 종료 코드 1 | 22/22 통과 |
| `python -I guide_sim.py` | 판단 순서 시뮬레이션, `guide_sim_result.md` 다시 만듦 | 21화면 중 AI 1 |
| `python -I mask.py` | 가리기 패턴 시험 | 「없음」 |

- 시험 화면은 `fixtures/`에 있습니다. 실제 폰 화면(xml)과 AI 답 기록에서 **주소 · 가게 지점 이름 · 최근 목적지 · 자주 가는 곳을 「○○」이나 「[가림]」으로 바꾼 사본**입니다. 스크린숏(png)은 넣지 않았습니다
- 원본 화면 · 스크린숏은 개인정보가 있어 김우석 PC에만 있습니다
